# ADR 0048 · Ask 本地会话历史、7 天淘汰策略与 Slash 命令

- Status: Accepted
- Date: 2026-09-22
- Context: ADR 0045（Ask 目录常驻 Agent）、ADR 0042（Ask BYOK 生成）与 ADR 0037（个人开源记忆库定位）

## Context

Ask Asterism 经过 ADR 0042 / 0044 / 0045 / 0046 的落地，已形成稳定的「客户端 BYOK + 目录常驻浅层 Agent + 无状态 Edge Function 透传」体系。然而，当前前端将多轮问答状态保存在内存 React state 中，刷新页面或触发重置会导致先前的问答推理和推荐卡片完全丢失。用户在进行多轮对比与技术选型时，有回看近期分析结论并继续追问的明确需求。但若直接引入 ChatGPT 式的独立全屏聊天或侧栏会话列表，会使 Asterism 滑向通用 AI 聊天工具，破坏「以仓库和记忆为主、Ask 为全局辅助」的极简心智，并带来不必要的云端数据库存储负担。

## Decision

1. **定位为「轻量对比工作台」**：确认多轮推理与对比结论具备独立回看价值；但依然坚守常驻底部的 Liquid Glass 对话舱（`AskDock`），不新增独立的全屏 `/ask` 路由或侧栏二级列表，保持 Asterism 以仓库资产为主的纯净心智。
2. **纯浏览器本地存储（IndexedDB）**：会话数据完全持久化在客户端 IndexedDB（对象库 `sessions`，异常降级至 localStorage），零服务端 migration、零 Supabase 数据存储成本，严格契合客户端 BYOK 的私有无状态原则。
3. **自然时间驱动为主的淘汰策略（7 天窗口 + 保底 5 场 / 上限 30 场）**：
   - 超过 7 天未更新的会话在进入应用时自动静默清理。
   - 保底规则：若清理后会话少于 5 场，至少保留最新的 5 场（防止用户休假一周后历史全空）。
   - 上限规则：按 `updatedAt` 倒序最多保留 30 场（防止高频使用下列表无限膨胀）。
4. **输入框 Slash Command（`/`）唤起体系**：
   - 输入框以 `/` 开头时向上呼出轻量毛玻璃命令菜单，支持键盘 `↑↓` 导航与 `Enter` / `Tab` 补全。
   - 极简核心命令集：`/history`（切换至历史会话列表视图）与 `/new`（开启空白新对话并自动存盘旧会话）。不提供破坏性的 `/clear` 指令，防误操作丢失记录。
5. **舱内原地视图切换（In-Dock View Switch）与搜索协同**：
   - 触发 `/history` 后，现有的 Liquid Glass 展开舱原地平滑切换为历史会话列表视图。
   - 底部输入框无缝转为实时搜索框（占位符 `搜索历史会话... (Esc 返回)`），输入文字即时过滤会话首问与摘要。
   - 全键盘友好：按 `↑↓` 直接在高亮项移动，按 `Enter` 载入目标会话并切回对话态，按 `Esc` 或「← 返回」原样退出。
   - 条目悬停提供单个删除按钮，列表顶部提供「清空全部历史」二次确认操作。
6. **完全可续聊（Resumable）与清爽初态（Clean Default）**：
   - 载入历史会话后，完整恢复其历史轮次（`turns`）与证据推荐卡片；底部输入框可直接继续追问，新问答追加进该会话并更新 `updatedAt`。
   - 初次打开网页或刷新页面时，保持清爽空白初态（Clean Default），不自动展开旧会话，防止上下文打扰。

## Trade-offs

- 会话保存在本地浏览器中，跨设备（不同电脑/手机）不自动漫游；但满足了单机日常轻度对比和防手滑丢记录的需求，且避免了将敏感问答文本同步到自部署数据库的隐私与容量顾虑。
- 淘汰规则采用「7 天 + 保底 5 / 上限 30」的混合机制，相比于纯 LRU 或纯时间截断增加了一点过滤计算，但彻底避免了“休假回来全空”或“极高频下单周会话爆仓”两端边缘极端体验。
- 舱内视图切换复用了现有 Liquid Glass 动画与高度约束，省去了新开弹窗或抽屉的层级冲突；限制是纵向滚动区受限于 `36rem`，但在单列表项高密度展示下可容纳充足的可见条目。
