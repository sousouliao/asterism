# ADR 0033 · 采用 Collection Dial 作为 Browse 直接整理入口

- Status: Superseded
- Date: 2026-08-12
- Superseded by: ADR 0036（2026-08-27）
- Builds on: ADR 0023、0026–0028、0032

## Context

AI 整理退役后，Asterism 仍需要一种由用户掌控、低摩擦的集合整理方式。既有 Quick Look 可以逐项编辑集合，批量整理可以处理明确选择范围，但两者都没有回答用户浏览仓库时如何把当前对象快速送入最可能的既有集合。

2026-08-06 至 2026-08-12 的开发态 throwaway prototype 先比较浅弧卡槽、Dock 纵深与明显轮盘，随后依据用户反馈收敛为底部半圆集合盘。用户否决了普通卡片沿弧线排列的方向，要求集合表现为可以张开、接住仓库的实体容器；后续迭代又把点击选择与写入确认分离，移除实体盆体、冗余箭头和装饰阴影，并用真实浏览器核验明暗主题、1536px / 390px 响应式、点击选择、Q/E + Enter、拖拽投放、失败重试与单次 Undo。

用户于 2026-08-12 明确判断当前原型方向可以推荐到真实实现。此前约定的桌面连续 10 项、移动连续 5 项任务没有形成单独的测量记录，原型也没有实现「更多集合」和「新建集合」承接，因此不能把这些项目记为已经验证。它们继续作为生产规格和实现验收项，而不再阻止对体验骨架作出产品决定。

## Decision

接受 Collection Dial 作为 Browse 中直接整理仓库的目标体验：

- 用户拿起仓库或已选范围后，底部临时出现由文件夹沿弧形轨道组成的集合盘；它不是页面、持久模式或自动任务。
- 当前目标进入中央。文件夹闭合表示可选容器，拖放命中或写入时打开，形成仓库被接住的直接反馈。
- 点击文件夹或 Q/E 只选择目标；Enter 或明确按钮确认写入。拖放到文件夹并在盘内松手可以一步确认，盘外松手或 Escape 取消。
- 候选在拿起时冻结。推荐只调整已有集合的顺序，信号可以来自本地语义近邻、已有关系和当前会话最近使用；无可信语义信号时静默退化，不自动写入 canonical，不采集推荐接受 / 拒绝日志，也不重新引入 Generation、Provider 或 BYOK。
- 单项与多选共享同一交互模型。多选继续遵守 ADR 0023 的稳定 repository ID 范围、逐关系幂等写入、持久执行、部分失败与精确重试边界。
- 权威成功前不宣告完成；失败保留范围和目标。每次成功具有独立短期 Undo，不能扩大为会话级回滚。
- 快速窗口之外必须由「更多集合」与「新建集合」承接冻结范围；创建成功后自动加入。
- 正式术语为「集合盘（Collection Dial）」。用户界面不使用「语义集合盘」「AI 推荐」或 Sparkles 标记。

## Prototype Verdict

原型已回答并接受的问题：

- 底部临时操作层优于新页面或常驻整理面板。
- 文件夹容器与打开接收态比普通卡片更能表达集合和投放。
- 半圆感应由文件夹空间排布建立，背景保持透明渐变模糊，不绘制实体盆体。
- 选择目标与确认写入必须分离；直接拖拽仍可保持一步投放。
- active 项居中、相邻项沿轨道移动，以及宽屏 / 窄屏奇数窗口可以成为生产方向。
- pending、failure、retry、cancel、success 和独立 Undo 应集中在同一个因果状态区。

原型未回答、必须进入规格或实现验收的问题：

- 「更多集合」搜索 / 选择与「新建集合」创建后的范围冻结、焦点和失败恢复。
- 真实数据下候选排名、无 embedding 降级、多选共识与已有关系过滤。
- 单项快速写入和持久批量写入如何共享接口，以及独立 Undo 的持久身份与冲突规则。
- 虚拟列表、Quick Look、选择模式和移动滚动中的拖动启动、误触与焦点协调。
- 连续桌面 10 项、移动 5 项的真实生产验收。

## Consequences

- 下一阶段进入 buildable spec，再拆 blockers-first tracer-bullet tickets；不直接把 `CollectionDialPrototype` 重命名或接上数据库。
- 原型在生产实现完整覆盖前保留为交互与视觉 primary source，生产入口不得挂载原型假数据或模拟计时器。
- `packages/core` 承担页面无关的候选与范围规则，`packages/ui` 承担可复用呈现和交互接口，数据访问只经 `packages/db`，Browse 负责平台组装。
- 「更多 / 新建」、真实候选、批量恢复、Undo 和连续任务验证仍是完成条件；接受方向不等于这些能力已经交付。
