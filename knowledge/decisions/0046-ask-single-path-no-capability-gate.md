# ADR 0046 · Ask 只保留一条路径，不做能力分级与同意重签

- Status: Accepted
- Date: 2026-09-21
- Amends: ADR 0045 第 5 条（能力分级降级）与第 6 条（v1 / v2 同意不得静默升级）
- Preserves: ADR 0045 的目录常驻、本地确定性工具、read gate、预算分轨；ADR 0042 的 BYOK 与无状态代理；ADR 0044 的流式 Markdown
- Implements: 单一 Agent 路径、纯连通性探针、同意向前迁移

## Context

ADR 0045 第 5 / 6 条给新架构加了两道门，上线后立刻把唯一的用户挡在门外。

**能力分级这道门是反向的。** 探针要求模型同时通过工具调用与长上下文定位两项，
任一不过就静默降级到 ADR 0042 的固定 top-K 召回。降级本身不可见：用户唯一能观察到的
症状是问「你好」得到「收藏库中未找到匹配项目」。判定还是默认拒绝——所有在探针升级前
建立的连接都没有 `mode` 字段，一律落到 `fixed`，于是所有既有连接在部署后立即失效。

更关键的是，分级保护的东西并不存在。不会调工具的模型走 Agent 路径不会崩：它照样拿到
完整目录，照样能就目录作答，只是没有任何 `expand` 记录，read gate 让推荐卡片为空。
那是**降级但可读**的结果。而固定召回路径的失败模式是 `tokenizeQuestion` 抽不出实义词
就直接 `not_found`——**更差**。用一条更差的路径去「保护」一条更好的路径，是设计错误。

**同意重签这道门解决的是别人的问题。** 出网范围确实从「至多 12 条候选」扩大到全库元数据，
这值得如实披露。但 Asterism 是自部署的个人工具：签同意的人、改架构的人、承担后果的人
是同一个。把 v2 同意作废、要求重新点一次确认，没有产生任何新的知情——披露文案本身
才是知情——只产生了一次无法解释的功能中断。

## Decision

1. **Agent 是唯一路径。** 删除固定召回流程及其全部代码（`selectAskCandidates`、
   `buildAskFixedPrompt`、`parseAskFixedResponse`）。不按模型能力分流。
   模型不调工具时正文照常呈现，推荐为空——这由 read gate 自然保证，不需要额外分支。

2. **探针只回答「这条连接能不能用」。** `test` 动作回到单次连通性检测，
   不再探测工具调用与长上下文，不再写入 `tools` / `longContext` / `mode`。
   既有连接记录里的这些字段被读取层忽略，无需用户重测。

3. **同意向前迁移。** 发现 v2 同意时直接迁到当前键并删除旧键，不作废、不重新索要确认。
   出网范围的变化由同意对话的披露文案承担（已写明「整份收藏库目录」）。
   v1 键存过明文 key 的快照，仍然读取即删除。

4. **模型不达标时失败要可见。** 不再用静默降级掩盖，用户看到的是这个模型给出的真实回答
   （可能没有推荐卡片），据此自行换模型。

## Consequences

- 既有连接与既有同意在部署后继续可用，不需要任何手工操作。
- 弱模型的体验由用户自己判断并选择，Asterism 不代替判断，也不代替沉默。
- Ask 的分支数减少一半：一条 prompt、一套解析、一个终止状态机。
- 若将来面向多用户托管部署，出网范围变更的再确认与模型准入需要重新立 ADR——
  本决策的前提是单用户自部署。
